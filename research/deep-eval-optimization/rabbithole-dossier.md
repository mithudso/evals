## 3. Deepening Passes (Pass 1–4)

### Pass 1: Leakage Mechanics & Prompt Decontamination (Pass F)
- **Tautological Prompting**: When developers write eval prompts after writing a skill, they unconsciously reuse distinctive adjectives, parameter names, or structural headings found in `SKILL.md`. For example, prompting "Generate an executive report with the 5 formal finding categories" forces the LLM to search its system prompt for "5 formal finding categories," artificially triggering the skill and feeding the answer.
- **Decontamination Transforms**: Pass F executes an n-gram overlap scanner between the test prompt and `SKILL.md`. Any 4-gram match that does not represent generic English or public domain terminology is flagged. The prompt is rewritten from the perspective of an end user who has never seen the skill file.

### Pass 2: Edge Cases & Failure Modes
- **Discriminative Inversion (Negative Delta)**: A poorly calibrated assertion tests for a convention that the base model adheres to natively, but that the skill intentionally alters (e.g. terse output vs verbose markdown). Armed with the skill, the agent fails the test, yielding $\Delta < 0$. Pass B identifies inverted assertions and verifies that assertions grade intended capability lift, not conflicting style preferences.
- **Synthetic Syntax Blindness (Pass A)**: Synthetic prompts generated by LLMs feature impeccably punctuated, complete sentences with explicit commands ("Please analyze the attached document and provide..."). Real users write: "why is this failing" with an error log. Evaluating agents solely on synthetic syntax creates skills that fail to trigger on real user workflows.
- **Silent Schema Drift (Pass L)**: An eval file with malformed field names (e.g. `evalId` instead of `eval_id`, or a string where an array is expected) is silently skipped by naive test runners, producing artificial 100% pass rates on 0 executed tests. Pass L enforces strict JSON schema validation before runner execution.

### Pass 3: Expert Disagreements & Contrarian Views
- **Static Handcrafted Evals vs Autonomous Synthetic Test Generation**:
  - *Synthetic Eval Proponents*: Claim that LLMs can generate 1000s of edge-case test cases in seconds, far outstripping human authoring bandwidth.
  - *Deep Eval Optimizer Engineers (AgentSkills Standard)*: Emphasize that un-audited synthetic test generation suffers from compounded hallucination, severe answer leakage, and lack of real-world messiness. 10 carefully audited, discriminative, realistic test cases (Passes A–L) provide vastly superior signal than 1,000 synthetic tautologies.
- **Strict Pass Gating vs Flexible Warning Linting**:
  - *Linter Advocates*: Argue that DEO passes should emit non-blocking warnings so developers can iterate quickly.
  - *Hardening Purists*: Insist that a failing Pass F (answer leakage) or Pass C (vibe assertion) completely invalidates benchmark integrity; releases must be hard-blocked until all 12 passes achieve PASS status.

### Pass 4: Mathematical Formulation
Let $\mathcal{T}$ be a test suite with test cases $\{t_1, \dots, t_N\}$.
Let $\mathcal{P}_k(t_i) \in \{0, 1\}$ denote whether test case $t_i$ passes analytical pass $k \in \{A, B, \dots, L\}$.
Suite Quality Score:
$$\mathcal{Q}_{\text{suite}}(\mathcal{T}) = \frac{1}{12 N} \sum_{k=A}^L \sum_{i=1}^N \mathcal{P}_k(t_i)$$
Discriminative Separation Index ($\text{DSI}$):
$$\text{DSI}(t_i) = \text{Score}_{\text{with\_skill}}(t_i) - \text{Score}_{\text{base\_model}}(t_i)$$
Pass B Invariant:
$$\mathcal{P}_B(t_i) = \mathbf{1}[\text{DSI}(t_i) \ge \tau_{\text{discrim}}], \quad \text{where } \tau_{\text{discrim}} = 0.20$$
Prompt Contamination Metric (Pass F):
$$\text{Overlap}(p_i, S) = \frac{|\text{N-grams}(p_i) \cap \text{N-grams}(S)|}{|\text{N-grams}(p_i)|}$$
$$\mathcal{P}_F(t_i) = \mathbf{1}[\text{Overlap}(p_i, S) \le \tau_{\text{leak}}]$$
